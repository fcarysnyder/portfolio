How the site's styles actually fit together

A style guide rebuilt from the code, not from Figma. Every value here was read out of src/, and each one notes where it's defined. The first half explains how the CSS gets assembled and what the audit found, with the findings the reading-typography work closed marked resolved. The second half is the style sheet itself, updated for the new type scale, type roles, red tokens, page header, article styles and reader controls.

The site's tokens are copied in at the top of this file, so it opens straight from disk with no build step. Toggle Dark to see the theme swap the way the site does it. Toggle Visitor font to see the page in the fallback font your visitors get (see finding F1).

01

How styles assemble

Several separate systems write CSS for this site. The order they apply in isn't top-to-bottom in a file. It comes from cascade layers, so the first thing to understand is which system wins. Since the reading-typography work, the shared type and article styles live in the layers too, so a utility class or a role class can finally override an element default.

Tailwind v4 puts everything it generates inside named @layers. The rule that trips people up: any CSS outside a layer beats every layered rule, regardless of specificity. What is left outside a layer is the palettes and component rules in global.css, plus every Astro <style> block. Those still beat Tailwind utilities and the new role classes, which is why a component <style> must not redeclare size, weight or color on an element that carries a role class.

weakest firststrongest last
1

Tailwind @layer theme

Writes every @theme token out as a :root custom property: --color-gray-200, --font-sans, --spacing-4, plus Tailwind's own defaults, including the whole --text-* size scale. These are only variables, not rules. global.css:5-53

2

Tailwind @layer base new: element defaults

First Preflight, the reset: it removes every margin and padding, sets h1–h6 { font-size: inherit; font-weight: inherit }, strips list styles and sets border: 0 solid. Then the site's own element defaults, in the same layer and after Preflight so they win without a specificity fight: body (font, color, line-height), h1–h5 (weight, color, line-height, no size), a (--accent-text), img and ::selection. global.css:173-208

3

Tailwind @layer components new

The type roles (.t-display, .t-page-title, .t-lead and the rest) and the shared article styles (.prose plus the reader hooks). They beat the element defaults in base, and utilities can still adjust them. styles/type.css · styles/prose.css

4

Tailwind @layer utilities

The utility classes actually used in templates: flex, flex-col, gap-2/4/8/20, lg:gap-48, mt-5, my-5, mb-3, sr-only, plus the custom @utility wrapper. Used for layout, not for type or color. global.css:55-60

5

Unlayered CSS beats 1–4 always

Still a large share of the styling, and every source has equal standing, so specificity and source order decide between them:

• global.css: the :root / :root.theme-dark palettes, focus rings, and the component rules .button, .menu-*, .nav-items, .link.
• Astro scoped <style> in most components and pages. Astro rewrites .title to .title[data-astro-cid-xyz], which adds one attribute's worth of specificity and limits the rule to that component's own markup. :global(...) turns the scoping off.
• React-injected <style> tags inside PhotoGallery, PhotoModal and CaseStudyCarousel, used for hover states that inline styles can't express. ReaderSettings.css, imported by the Aa panel island, is also unlayered.

6

Inline style=""

React style={{…}} objects in PasswordModal, PhotoModal, CaseStudyCarousel, PhotoGallery, GatedContent and ScrambleText (well over 100 declarations), plus per-instance variables like Pill's --pill-color.

7

!important 20 uses

11 in global.css (mostly the dropdown and secondary button), 7 in Footer.astro (where its desktop media query overrides its own base rules) and 2 in BackgroundEffect. The card title's !important went away with the type roles.

The original audit found that @theme defined --font-size-* and --font-family-*, which Tailwind v4 ignores, so text-lg was 1.125rem while var(--font-size-lg) was 1.25rem. The old names are gone from src/ (grep finds none), and every reference was remapped by value or role, never by name (commit ec1f4b9).

How theming works

  1. An inline script in MainHead.astro runs before first paint. It reads localStorage.theme, falls back to prefers-color-scheme, and toggles .theme-dark on <html>. It runs again after every View Transition swap. A second inline script in the same file does the same for reader preferences (see Typography).
  2. :root.theme-dark (global.css:138-165) inverts the gray ramp: --gray-0 goes from near-black to white and --gray-999 from white to near-black. It also swaps the accent text colors (--accent-text becomes #ff4949, its hover #ff7a7a), the shadows (dark shadows become white glows) and two gradients.
  3. Components only reference ramp steps, so none of them need theme logic. The exceptions are ThemeToggle.astro (:global(.theme-dark)), the home page's --icon-color (which has the same value in both themes), and BaseLayout's background images.

The upshot: the gray numbers mean distance from the background, not lightness. gray-0 is "strongest ink" and gray-999 is "the page". The model is a sound one. It just isn't named that way, which is why the ramp reads like a puzzle.

02

Findings

Ranked by how much each one affects what visitors see or how easy the CSS is to change. File references point at the branch as audited; line numbers in unresolved findings may have shifted. Findings resolved by the reading-typography work are marked and outlined with a dashed border, with the commit. They keep their original audit text, which describes the site before the change.

HighF1 · fonts

Aktiv Grotesk is never actually served to visitors

All four @font-face rules use only src: local(...) (global.css:73-99). No woff2 is in public/ and there's no Adobe Fonts kit. You see Aktiv Grotesk because it's installed on your Mac through Creative Cloud. Everyone else gets the next font in the stack: San Francisco on Apple devices, Segoe UI on Windows, Roboto on Android.

Your brand typeface is effectively a local preview. Click Visitor font in the top bar to see what most visitors get.

Fix: add the Adobe Fonts web project embed (Aktiv Grotesk is on Adobe Fonts) or self-host licensed woff2 files with font-display: swap. Keep the local() entries first if you like.
ResolvedF2 · color / a11y

The accent red fails WCAG AA for text in light mode

#ff4949 on white is 3.33:1, and AA needs 4.5:1 for normal-size text. Red text is used for every link, the back/prev/next links, footer socials, active filters, and the card CTA. The CTA is the worst case: 12px uppercase, the smallest text on the site at the lowest contrast. The primary button (white on red, 14px/600) is also 3.33:1. In dark mode the same red passes at 5.9:1.

Fix: split the accent into a fill role and a text role. Keep #ff4949 as the dark-mode text color and the decorative fill. For light-mode text and button fills use something like #d62828 (5.0:1 on white, 5.0:1 with white text on it). See the comparison in Color.
Resolved in fa7b83d. The accent split into a brand red and accessible text/fill reds. Light-mode text and every button fill use #d62828 (5.0:1 on white and under white text); dark-mode text keeps #ff4949 (5.9:1). Dark-mode buttons also moved to #d62828, because white on #ff4949 fails in both themes. Measured values are in Color.

ResolvedF4 · typography

The site has a type system in practice, but no single place defines it

The h1–h5 defaults in global.css:252-281 (h1 = 4.5rem, h2 = 3.5rem…) are overridden everywhere they appear, so they describe a site that doesn't exist. The real roles (see Typography) are redeclared page by page:

  • Page title (2xl → 3xl at 60em, gray-0) is written out 6 times: Hero.astro:32, AboutHero.astro:31, photography/index:37, writing/index:95, writing/[...slug]:116, work/[...slug]:133.
  • Hero tagline is hardcoded at 1.5rem/2rem in 3 places. 1.5rem isn't a step on your scale, which jumps from lg 1.25 to xl 1.625.
  • Card title is 24px !important in gray-200, while every other title is gray-0 (PortfolioPreview.astro:113).
  • --font-size-4xl, -5xl and -md aren't used by anything live.
  • SectionHeader renders its 14px uppercase label as an <h3>, so the document outline jumps from h1 to h3.
Fix: name the roles (display, title, heading, subheading, lead, body, label, meta, caption) as classes in one file. Then set the global h1–h5 rules to what pages really use, or delete them.
Resolved in a480481. The nine roles are classes in src/styles/type.css (.t-display, .t-page-title, .t-summary, .t-eyebrow, .t-lead, .t-section-heading, .t-subheading, .t-meta, .t-small-link), and every page uses them. The global h1–h5 defaults no longer carry a size. The !important on the card title is gone. The SectionHeader outline issue (h3 for a label) was not part of this change and is still open.

MediumF6 · dead CSS

About 100 lines of Nav styles never apply

The dropdown markup comes from the React island NavDropdown.tsx. Astro's scoped styles only reach markup in the same .astro template, so the .menu-button, .menu-content, .nav-items, .link, .socials and .social rules in Nav.astro:79-175 match nothing. The live versions are the global ones in global.css:285-370, and their values conflict (for example .nav-items gap 1rem vs 4px, padding 2rem vs 8px).

Other dead rules: [data-theme='light'] .menu-button (global.css:315; the site never sets data-theme), .hero p and .roles in index.astro:99-106 and 145-149, and the unused component HeroTyper.tsx.

Fix: delete them. If you want the dropdown styles next to the component, move them into a CSS file that NavDropdown.tsx imports.
MediumF7 · architecture

Component styles sit in global scope with generic names

.button, .link, .menu-button and .nav-items are unlayered global classes. .button also carries margin-top: 20px, a layout decision inside a component. Because they're unlayered, adding a utility like class="button mt-0" won't remove that margin (see the cascade above). .link is generic enough that it'll collide with something eventually.

Fix: wrap component rules in @layer components { … } so utilities can override them, and drop the margin from .button.
ResolvedF8 · color

Nine reds, and the hover state is barely visible

Light-mode hover goes from #ff4949 to #f54c4c, which is almost the same color, so hovering a button or link shows almost no change. The naming is also reversed: --accent-light is #600202, the darkest red, and nothing uses it. Hardcoded reds appear in PasswordModal (hsl(0 80% 60%), hsl(0 80% 65%)), BackgroundEffect (#ff4949 fallback) and gradients (#ca7879).

Fix: --accent, --accent-hover (a visible 8–12% shift), --on-accent and --danger. That's four roles, each with a light and dark value.
Resolved in fa7b83d. Seven tokens replaced nine reds: --brand, --accent-text, --accent-text-hover, --accent-fill, --accent-fill-hover, --on-accent and --accent-overlay-hover. Hover is now a visible step (#d62828 to #b71c1c in light mode, #ff4949 to #ff7a7a in dark). The old --accent-regular/-dark/-light/-overlay and --link-color are removed. A --danger token was not added, so the PasswordModal error reds are still hardcoded.
MediumF9 · React

React components style themselves with inline objects

PasswordModal, PhotoModal and CaseStudyCarousel each build the same overlay chrome by hand: rgba(0,0,0,.9) backdrop, white ✕ at 2rem, ‹ › arrows at 2.5rem and 1rem insets. Inline styles can't express :hover, :focus-visible or media queries, which is why two of them inject <style> tags. The password field's focus state relies on the global outline only.

Fix: a small overlay.css (backdrop, close, prev/next) imported by the three components.

LowF12 · scales

Radius, spacing and breakpoints have no shared scale

  • 13 distinct radii: 2px, 0.25, 0.375, 0.5rem, 8px, 0.75, 0.9375, 1rem, 20px, 1.5rem, 50%, 999px, 999rem.
  • Spacing tokens exist, but only Tailwind utilities use them. Scoped CSS writes raw values (40px, 24px, 2.5rem, 3.5rem…).
  • Five breakpoints: 50em, 59.99em / 60em, 64em (written as 1024px in Footer), 70em. Tailwind only knows lg = 60em, and its sm/md/xl are still the defaults.
  • The 83rem wrapper is redefined by hand in Nav.astro:58-61 and Footer.astro:32-38 instead of using .wrapper. The reading-column grid (1fr 60% 1fr) is copied 3 times.
LowF13 · Tailwind scanning

Tailwind generates utilities from words that aren't classes

The built CSS includes .start{inset-inline-start:…}, .container, .table, .grid, .hidden, .border and .resize. Tailwind found them in prose and props. Hero's align="start" becomes class="start", which then matches the Tailwind utility as well as Hero's own .start. It's harmless today, but it's a namespace collision waiting to happen. @source not for the content folders would tighten this up.

The original plan for this branch. Steps the reading-typography work completed are checked off, with the commits. Each step is small enough to review by itself, and the order keeps the visual changes separate from the plumbing.

  2. Delete dead CSS. Remove the Nav.astro dropdown rules, the data-theme rule, the index.astro leftovers, HeroTyper and the unused tokens (F6, F11). This should change nothing visually, so it's a good first refactor to check against screenshots. open

  4. Add a semantic layer on top of the ramp. The red half is done: --brand, --accent-text, --accent-text-hover, --accent-fill, --accent-fill-hover, --on-accent, with the contrast fixed (F2, F8, fa7b83d). The gray half (--fg, --border, --surface…) and --danger are not. partly done
  5. Type roles in one file. src/styles/type.css defines nine .t-* roles (a480481), and src/styles/prose.css plus PageHeader.astro replace the two prose copies and the page-title copies (F4, F5, 0a9ebe9). done
  6. Layer it. Element defaults are in @layer base, and the roles and .prose are in @layer components. The old global component rules (.button, nav dropdown) are still unlayered, the overlay styles are not extracted, and the !importants remain (F7, F9). partly done
  7. Reader controls. Not in the original audit. Persisted preferences applied before paint (e8dc511) and the Aa panel (ef80c07). done

Where the file shape landed: global.css still holds tokens, palettes and the remaining component rules, and now imports type.css and prose.css. The proposed split into tokens.css / base.css / components.css is not done.

04

Color

One 12-step blue-gray ramp that inverts between themes, plus a red that is split by job: a brand red for decoration, and accessible reds for text and fills. The ramp numbers mean "distance from the background": 0 is the strongest ink and 999 is the page itself.

Contrast is measured against that theme's page background (gray-999); the fill row is white --on-accent text against the fill. AA ≥ 4.5 · AA large ≥ 3 · fail < 3. Gray usage counts are from the original audit and exclude global.css itself.

Reader controls

Blog posts and case studies get an "Aa" button in the nav, immediately left of the theme toggle. It opens a panel (components/ReaderSettings.tsx) with three settings and a reset. The choice is saved in localStorage as reader-prefs and applied as data-reader-font|size|leading on <html> by an inline script in MainHead.astro before paint and after every View Transition swap (lib/reader-prefs.ts).

  • Font: Sans (Aktiv Grotesk) or Serif (Literata). Default Sans.
  • Size: 14 / 16 / 18 / 20px, on the .prose base (text-sm / base / lg / xl). Default 16.
  • Line spacing: 1.5 / 1.7 / 1.9. Default 1.7.
  • Scope: only .prose, and only inside a page-level [data-reader-enabled] wrapper, so a saved preference never restyles the header, nav, footer, meta, About or the index pages. Everything inside .prose is in em, so the hierarchy scales with the setting.

Why the bad ideas look shippable

Low fidelity is for problem-seeking. High fidelity is for problem-solving. The order matters, because once you invest in visual polish, the sunk cost makes it harder to change the structure underneath.

Choose the setting, not the size

Every heading, margin and caption in the article is in em, so it moves with the base size and the proportions between them hold at all four sizes.

This is a demo of the same hooks as prose.css:148-172. The real panel is the Aa button on any post or case study.
