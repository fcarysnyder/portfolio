How the site's styles actually fit together

A style guide rebuilt from the code, not from Figma. Every value here was read out of src/, and each one notes where it's defined. The first half explains how the CSS gets assembled and what the audit found, with the findings the reading-typography work and the Tailwind cleanup closed marked resolved. The second half is the style sheet itself, updated for the new type scale, type roles, red tokens, page header, article styles and reader controls.

The site's tokens are copied in at the top of this file, so it opens straight from disk with no build step. Toggle Dark to see the theme swap the way the site does it.

01

How styles assemble

Almost all of the site's styling is Tailwind classes in the markup, and the little CSS that is left is in cascade layers. The order rules apply in doesn't come from where they sit in a file. It comes from the layers, so the first thing to understand is which one wins. The full write-up, with how to add a style, is in docs/css-architecture.md.

Tailwind v4 puts everything it generates inside named @layers, and the site's own CSS joins the same ones. The rule that trips people up: any CSS outside a layer beats every layered rule, regardless of specificity. That is why the unlayered row below is almost empty, and why there is no !important left in src/: a utility class always beats a role, and a role always beats an element default.

weakest firststrongest last
1

Tailwind @layer theme

Writes the @theme tokens out as :root custom properties: --color-gray-200, --font-sans, --spacing-4, plus Tailwind's own defaults, including the whole --text-* size scale. These are only variables, not rules. Tailwind writes out only the ones something uses. global.css · @theme

2

Tailwind @layer base

First Preflight, the reset: it removes every margin and padding, sets h1–h6 { font-size: inherit; font-weight: inherit }, strips list styles and sets border: 0 solid. Then the site's own element defaults, in the same layer and after Preflight so they win without a specificity fight: html / body sizing, body (font, color, line-height), h1–h5 (weight, color, line-height, no size), a (--accent-text), img, ::selection and the global focus ring. global.css · @layer base

3

Tailwind @layer components

The type roles (.t-display, .t-page-title, .t-lead and the rest) and the shared article styles (.prose plus the reader hooks). Both are all-layered. They beat the element defaults in base, and a utility can still adjust them. styles/type.css · styles/prose.css

4

Tailwind @layer utilities

The classes written in templates: layout, spacing, color, borders, hover and focus states, breakpoints (lg: is 60em), dark mode (dark: follows .theme-dark). Plus the site's own @utility rules: wrapper and elevation-sm/md/lg. This is where nearly all component and page styling lives. markup · global.css · @utility

5

Unlayered CSS beats 1–4 always

Kept as small as possible. The whole list:

• global.css: the :root / :root.theme-dark token blocks. Variables, not rules, so nothing competes with them, and dark mode has to redefine them. They are the only unlayered rules in our CSS files.
• @keyframes (the three --animate-* in @theme) and Tailwind's @property registrations. Not rules that match elements, so layers don't apply.
• about.astro: five hover-cursor rules whose values are emoji SVG data URIs. It is the only <style> left, and it carries a "Why not Tailwind:" comment.
• Library CSS: Astro's route announcer and view-transition keyframes, and react-tweet's stylesheet on pages with an embedded tweet.

6

Inline style="" custom properties only

Three uses, each setting a variable from data that a class then reads: Pill's --pill-color, PortfolioPreview's per-card --on-accent, and PhotoGallery's --aspect. Everything else that used to be an inline style object (the modals, lightboxes, gallery) is now classes. A few scripts still set a style at runtime for state: the carousel's transform, body scroll lock and the background blur.

7

!important 0 uses in src/

There were 20 before the cleanup. A test fails if one comes back, including Tailwind's ! modifier. Library CSS still has a few (Preflight's [hidden] rule, Astro's reduced-motion rule).

The old names are gone from src/ (grep finds none), and every reference was remapped by value or role, never by name (commit ec1f4b9).

How theming works

  1. An inline script in MainHead.astro runs before first paint. It reads localStorage.theme, falls back to prefers-color-scheme, and toggles .theme-dark on <html>. It runs again after every View Transition swap. A second inline script in the same file does the same for reader preferences (see Typography).
  2. :root.theme-dark (global.css) inverts the gray ramp: --gray-0 goes from near-black to white and --gray-999 from white to near-black. Red text doesn't change with the theme; the fills deepen to #e03e3e (hover #cc3838) so buttons don't glare. It also swaps the shadows (dark shadows become white glows) and one gradient.
  3. Components reference ramp steps or tokens, so almost none need theme logic. Where one does, it uses the dark: variant, which follows .theme-dark on <html>, not the OS setting.

The upshot: the gray numbers mean distance from the background, not lightness. gray-0 is "strongest ink" and gray-999 is "the page". The model is a sound one. It just isn't named that way, which is why the ramp reads like a puzzle.

02

Findings

Ranked by how much each one affects what visitors see or how easy the CSS is to change. File references point at the branch as audited; line numbers in unresolved findings may have shifted. Findings resolved by the reading-typography work are marked and outlined with a dashed border, with the commit. They keep their original audit text, which describes the site before the change.

HighF1 · fonts

Aktiv Grotesk is never actually served to visitors

All four @font-face rules use only src: local(...) (global.css:73-99). No woff2 is in public/ and there's no Adobe Fonts kit. You see Aktiv Grotesk because it's installed on your Mac through Creative Cloud. Everyone else gets the next font in the stack: San Francisco on Apple devices, Segoe UI on Windows, Roboto on Android.

Your brand typeface is effectively a local preview.

Fix: add the Adobe Fonts web project embed (Aktiv Grotesk is on Adobe Fonts) or self-host licensed woff2 files with font-display: swap. Keep the local() entries first if you like.
Resolved by switching fonts. Aktiv Grotesk is gone. The sans is now Mona Sans (GitHub, open source), served from Google Fonts as one variable file (weights 400–700, with italics), so every visitor gets it. The unused Public Sans and Rubik request was replaced in the same change.
ResolvedF2 · color / a11y

The accent red fails WCAG AA for text in light mode

#ff4949 on white is 3.33:1, and AA needs 4.5:1 for normal-size text. Red text is used for every link, the back/prev/next links, footer socials, active filters, and the card CTA. The CTA is the worst case: 12px uppercase, the smallest text on the site at the lowest contrast. The primary button (white on red, 14px/600) is also 3.33:1. In dark mode the same red passes at 5.9:1.

Fix: split the accent into a fill role and a text role. Keep #ff4949 as the dark-mode text color and the decorative fill. For light-mode text and button fills use something like #d62828 (5.0:1 on white, 5.0:1 with white text on it). See the comparison in Color.
Resolved in fa7b83d. The accent split into a brand red and accessible text/fill reds. Light-mode text and every button fill use #d62828 (5.0:1 on white and under white text); dark-mode text keeps #ff4949 (5.9:1). Dark-mode buttons also moved to #d62828, because white on #ff4949 fails in both themes. Measured values are in Color.
Updated since. The branch then tried AAA reds at the logo's hue (#b60000 text, #ff6969 fills with dark text). The owner judged both versions worse to look at and rolled the colors back to main: #ff4949 for text and fills, hovers #f54c4c, white text on fills. (Later: dark mode's hover went from main's lighter #f86161 to the same deeper #f54c4c.) The role tokens stay, so a later change is one edit. This finding is open again, as an accepted gap.

ResolvedF4 · typography

The site has a type system in practice, but no single place defines it

The h1–h5 defaults in global.css:252-281 (h1 = 4.5rem, h2 = 3.5rem…) are overridden everywhere they appear, so they describe a site that doesn't exist. The real roles (see Typography) are redeclared page by page:

  • Page title (2xl → 3xl at 60em, gray-0) is written out 6 times: Hero.astro:32, AboutHero.astro:31, photography/index:37, writing/index:95, writing/[...slug]:116, work/[...slug]:133.
  • Hero tagline is hardcoded at 1.5rem/2rem in 3 places. 1.5rem isn't a step on your scale, which jumps from lg 1.25 to xl 1.625.
  • Card title is 24px !important in gray-200, while every other title is gray-0 (PortfolioPreview.astro:113). Now gray-0 like the rest.
  • --font-size-4xl, -5xl and -md aren't used by anything live.
  • SectionHeader renders its 14px uppercase label as an <h3>, so the document outline jumps from h1 to h3.
Fix: name the roles (display, title, heading, subheading, lead, body, label, meta, caption) as classes in one file. Then set the global h1–h5 rules to what pages really use, or delete them.
Resolved in a480481. The ten roles are classes in src/styles/type.css (.t-display, .t-page-title, .t-article-title, .t-summary, .t-eyebrow, .t-lead, .t-section-heading, .t-subheading, .t-meta, .t-small-link), and every page uses them. The global h1–h5 defaults no longer carry a size. The !important on the card title is gone. The SectionHeader outline issue (h3 for a label) was not part of this change and is still open.

ResolvedF7 · architecture

Component styles sit in global scope with generic names

.button, .link, .menu-button and .nav-items are unlayered global classes. .button also carries margin-top: 20px, a layout decision inside a component. Because they're unlayered, adding a utility like class="button mt-0" won't remove that margin (see the cascade above). .link is generic enough that it'll collide with something eventually.

Fix: wrap component rules in @layer components { … } so utilities can override them, and drop the margin from .button.
Resolved by the Tailwind cleanup. .button, .link, .menu-* and .nav-items are gone as CSS rules: the styling is classes on the elements (button survives only as a hook class), so a utility such as mt-0 overrides it. The one unlayered scoped block left is about.astro's cursors.

LowF12 · scales

Radius, spacing and breakpoints have no shared scale

  • 13 distinct radii: 2px, 0.25, 0.375, 0.5rem, 8px, 0.75, 0.9375, 1rem, 20px, 1.5rem, 50%, 999px, 999rem.
  • Spacing tokens exist, but only Tailwind utilities use them. At audit time scoped CSS wrote raw values (40px, 24px, 2.5rem, 3.5rem…). That scoped CSS is gone; where an exact value is off the scale, a class now uses an arbitrary value (gap-[10px]) instead of rounding.
  • Five breakpoints: 50em, 59.99em / 60em, 64em (written as 1024px in Footer), 70em. Tailwind only knows lg = 60em, and its sm/md/xl are still the defaults.
  • The 83rem wrapper is redefined by hand in Nav.astro:58-61 and Footer.astro:32-38 instead of using .wrapper. The reading-column grid (1fr 60% 1fr) is copied 3 times.

The built CSS includes .start{inset-inline-start:…}, .container, .table, .grid, .hidden, .border and .resize. Tailwind found them in prose and props. Suggested cleanup order

The original plan for this branch. Steps the reading-typography work completed are checked off, with the commits. Each step is small enough to review by itself, and the order keeps the visual changes separate from the plumbing.

  1. Serve the font. Done by switching to Mona Sans from Google Fonts, which also dropped Public Sans and Rubik (F1, F10). Roboto Mono still loads its full weight range. partly done
  2. Delete dead CSS. The Nav, data-theme, index.astro and HeroTyper leftovers went with the Tailwind cleanup (F6). The unused gray and gradient tokens (F11) are still there. partly done
  3. Rename tokens to the v4 namespaces. --text-* and --font-* are done (F3, ec1f4b9). --radius-* and --breakpoint-* are not (F12). partly done
  4. Add a semantic layer on top of the ramp. The red half is done: --brand, --accent-text, --accent-text-hover, --accent-fill, --accent-fill-hover, --on-accent, with the contrast fixed (F2, F8, fa7b83d). The gray half (--fg, --border, --surface…) and --danger are not. partly done
  5. Type roles in one file. src/styles/type.css defines the .t-* roles (ten at a480481, eleven with .t-link), and src/styles/prose.css plus PageHeader.astro replace the two prose copies and the page-title copies (F4, F5, 0a9ebe9). done
  6. Layer it. Element defaults are in @layer base, the roles and .prose are in @layer components, and component and page styling is Tailwind classes in the utilities layer. The old global component rules are gone, the overlays use classes, and there is no !important in src/ (F7, F9). Only the token blocks, keyframes, About's cursors and library CSS stay unlayered. done
  7. Reader controls. Not in the original audit. Persisted preferences applied before paint (e8dc511) and the Aa panel (ef80c07). done

Where the file shape landed: global.css holds @theme, the token blocks, the custom variants and utilities, and the element defaults, and imports type.css and prose.css. The proposed split into tokens.css / base.css / components.css was not needed. See docs/css-architecture.md.

04

Color

One 12-step blue-gray ramp that inverts between themes, plus the original brand red for text and fills (below AA on white, an accepted gap), read through role tokens. The ramp numbers mean "distance from the background": 0 is the strongest ink and 999 is the page itself.

Contrast is measured against that theme's page background (gray-999); the fill row is --on-accent text against the fill. AAA ≥ 7 · AA ≥ 4.5 · AA large ≥ 3 · fail < 3. Gray usage counts are from the original audit and exclude global.css itself.

Scale

Tailwind's default --text-* scale is the only size scale. It is not redefined in @theme, every font size in src/ resolves to one of these steps, and there are no px sizes or !important on type except two documented exceptions: the BackgroundEffect debug panel (12px, an easter egg) and the emoji-cursor SVG data URIs in about.astro. Faded rows aren't used by any live code. Counts are references to var(--text-*), text-* or text-(length:--text-*) under src/, as of the Tailwind cleanup. .prose headings are in em and land on 2xl and xl without referencing them.

Roles

Each role is defined once, as a class in src/styles/type.css (or, for body and the in-article headings, in prose.css), and used the same way on every page. Specimens below use the same declarations as the source. Sizes shown as "A → B" change at the 60em breakpoint. The Work index and 404 used to borrow the home hero; they now use Page title, so only the home page shows the display size.

Reader controls

Blog posts and case studies get an "Aa" button in the nav, immediately left of the theme toggle. It opens a panel (components/ReaderSettings.tsx) with three settings and a reset. The choice is saved in localStorage as reader-prefs and applied as data-reader-font|size|leading on <html> by an inline script in MainHead.astro before paint and after every View Transition swap (lib/reader-prefs.ts).

  • Font: Sans (Mona Sans) or Serif (Literata). Default Sans.
  • Size: 14 / 16 / 18 / 20px, on the .prose base (text-sm / base / lg / xl). Default 18. The headings are calc(4em / 3) and calc(10em / 9), so at 18px they are exactly 24px and 20px, and they scale with the setting.
  • Line spacing: 1.5 / 1.7 / 1.9. Default 1.7.
  • Scope: only .prose, and only inside a page-level [data-reader-enabled] wrapper, so a saved preference never restyles the header, nav, footer, meta, About or the index pages. Everything inside .prose is in em, so the hierarchy scales with the setting.

Why the bad ideas look shippable

Low fidelity is for problem-seeking. High fidelity is for problem-solving. The order matters, because once you invest in visual polish, the sunk cost makes it harder to change the structure underneath.

07

Radius, shadow, motion

Radii in use (13)

Suggested consolidation: --radius-sm: 0.5rem (buttons, inputs, menus) · --radius-md: 0.75rem (cards, modals) · --radius-lg: 1.5rem (images, desktop cards) · --radius-full: 999px (pills, toggles). Everything else maps onto one of these four.

Shadows

--shadow-sm · cards, photos
--shadow-md · hover, images, modal
--shadow-lg · dropdown menu

Each one is four stacked layers. In dark mode they become faint white glows (toggle Dark to compare), which barely show against #090b11, so dark mode effectively has no elevation.

Motion

  • --theme-transition: 0.2s ease-in-out: link underlines, card shadow, filters, theme toggle. 15 references in src/. One hardcoded 0.2s ease in Hero.
  • Animations are registered as --animate-* in @theme, so they are classes: animate-modal-fade-in (0.2s, the lightboxes), animate-reader-fade-in (0.15s, the Aa panel) and animate-fade-in-from-top (1s, 10px, the home page intro, once per session).
  • ThemeToggle and the Aa panel wrap their motion in motion-safe:. The About carousel and the three.js background run regardless.

60em (960px) is the real breakpoint, registered as Tailwind's lg: lg: applies from 60em up and max-lg: below it. The other three are one-off values written as arbitrary variants.

Solid markers are in the site CSS. Dashed markers are the Tailwind defaults still active for sm/md/xl (40, 48, 80rem). The scale runs 0–90em.
