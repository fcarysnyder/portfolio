How the site's styles actually fit together

A style guide rebuilt from the code, not from Figma. Every value here was read out of src/, and each one notes where it's defined. The first half explains how the CSS gets assembled and what's wrong with it. The second half is the style sheet itself.

The site's tokens are copied in at the top of this file, so it opens straight from disk with no build step. Toggle Dark to see the theme swap the way the site does it. Toggle Visitor font to see the page in the fallback font your visitors get (see finding F1).

01

How styles assemble

Five separate systems write CSS for this site, and they don't share a convention. The order they apply in isn't top-to-bottom in a file. It comes from cascade layers, so the first thing to understand is which system wins.

Tailwind v4 puts everything it generates inside named @layers. The rule that trips people up: any CSS outside a layer beats every layered rule, regardless of specificity. All of global.css (except the @theme block) and every Astro <style> block sits outside a layer. So Tailwind utility classes are the weakest styles on the site, not the strongest.

weakest firststrongest last
1

Tailwind @layer theme

Writes every @theme token out as a :root custom property: --color-gray-200, --font-size-lg, --spacing-4, plus Tailwind's own defaults (--text-lg, --font-mono). These are only variables, not rules. global.css:3-63

2

Tailwind @layer base (Preflight)

The reset. Removes every margin and padding, sets h1–h6 { font-size: inherit; font-weight: inherit }, strips list styles and sets border: 0 solid. So any spacing a page has, it adds itself.

3

Tailwind @layer utilities

The utility classes actually used in templates: flex, flex-col, gap-2/4/8/20, lg:gap-48, mt-5, my-5, mb-3, sr-only, plus the custom @utility wrapper. About 20 distinct classes across the whole site, used for layout only and never for type or color. global.css:65-70

4

Unlayered CSS beats 1–3 always

Most of the site's styling sits here, and every source has equal standing, so specificity and source order decide between them:

• global.css: the :root / :root.theme-dark palettes, body, h1–h5 defaults, a, focus rings, and the component rules .button, .menu-*, .nav-items, .link.
• Astro scoped <style> in 18 files. Astro rewrites .title to .title[data-astro-cid-xyz], which adds one attribute's worth of specificity and limits the rule to that component's own markup. :global(...) turns the scoping off, which happens 69 times.
• React-injected <style> tags inside PhotoGallery, PhotoModal and CaseStudyCarousel, used for the hover states that inline styles can't express.

5

Inline style=""

React style={{…}} objects in PasswordModal, PhotoModal, CaseStudyCarousel, PhotoGallery, GatedContent and ScrambleText (well over 100 declarations), plus per-instance variables like Pill's --pill-color.

6

!important 21 uses

11 in global.css (mostly the dropdown and secondary button), 7 in Footer.astro (where its desktop media query overrides its own base rules), 2 in BackgroundEffect, and 1 on the card title.

How a token reaches the page

Colors take one path, while type and fonts take another, and part of that second path is broken.

redefined under :root.theme-dark

I confirmed this in the built CSS (dist/_astro/BaseLayout.*.css): .text-lg{font-size:var(--text-lg)} with --text-lg:1.125rem. The comment at global.css:26 says these are "project's actual values, NOT Tailwind defaults", but that isn't what happens. It hasn't caused a visible bug yet because no template uses a text-* or font-* utility. The first one someone adds will look slightly off.

How theming works

  1. An inline script in MainHead.astro:49-68 runs before first paint. It reads localStorage.theme, falls back to prefers-color-scheme, and toggles .theme-dark on <html>. It runs again after every View Transition swap.
  2. :root.theme-dark (global.css:162-202) inverts the gray ramp: --gray-0 goes from near-black to white and --gray-999 from white to near-black. It also swaps the accent hover color, the shadows (dark shadows become white glows) and two gradients.
  3. Components only reference ramp steps, so none of them need theme logic. The exceptions are ThemeToggle.astro (:global(.theme-dark)), the home page's --icon-color (which has the same value in both themes), and BaseLayout's background images.

The upshot: the gray numbers mean distance from the background, not lightness. gray-0 is "strongest ink" and gray-999 is "the page". The model is a sound one. It just isn't named that way, which is why the ramp reads like a puzzle.

02

Findings

Ranked by how much each one affects what visitors see or how easy the CSS is to change. File references point at the current branch.

HighF1 · fonts

Aktiv Grotesk is never actually served to visitors

All four @font-face rules use only src: local(...) (global.css:73-99). No woff2 is in public/ and there's no Adobe Fonts kit. You see Aktiv Grotesk because it's installed on your Mac through Creative Cloud. Everyone else gets the next font in the stack: San Francisco on Apple devices, Segoe UI on Windows, Roboto on Android.

Your brand typeface is effectively a local preview. Click Visitor font in the top bar to see what most visitors get.

Fix: add the Adobe Fonts web project embed (Aktiv Grotesk is on Adobe Fonts) or self-host licensed woff2 files with font-display: swap. Keep the local() entries first if you like.
HighF2 · color / a11y

The accent red fails WCAG AA for text in light mode

#ff4949 on white is 3.33:1, and AA needs 4.5:1 for normal-size text. Red text is used for every link, the back/prev/next links, footer socials, active filters, and the card CTA. The CTA is the worst case: 12px uppercase, the smallest text on the site at the lowest contrast. The primary button (white on red, 14px/600) is also 3.33:1. In dark mode the same red passes at 5.9:1.

Fix: split the accent into a fill role and a text role. Keep #ff4949 as the dark-mode text color and the decorative fill. For light-mode text and button fills use something like #d62828 (5.0:1 on white, 5.0:1 with white text on it). See the comparison in Color.
HighF3 · tokens

Type and font tokens use Tailwind v3 names, so there are two parallel scales

@theme defines --font-size-* and --font-family-*. Tailwind v4 reads --text-* and --font-*. The values are still emitted as variables, so var(--font-size-lg) works, but every Tailwind type utility silently falls back to Tailwind's defaults. Six of the ten steps differ:

MediumF4 · typography

The site has a type system in practice, but no single place defines it

The h1–h5 defaults in global.css:252-281 (h1 = 4.5rem, h2 = 3.5rem…) are overridden everywhere they appear, so they describe a site that doesn't exist. The real roles (see Typography) are redeclared page by page:

  • Page title (2xl → 3xl at 60em, gray-0) is written out 6 times: Hero.astro:32, AboutHero.astro:31, photography/index:37, writing/index:95, writing/[...slug]:116, work/[...slug]:133.
  • Hero tagline is hardcoded at 1.5rem/2rem in 3 places. 1.5rem isn't a step on your scale, which jumps from lg 1.25 to xl 1.625.
  • Card title is 24px !important in gray-200, while every other title is gray-0 (PortfolioPreview.astro:113).
  • --font-size-4xl, -5xl and -md aren't used by anything live.
  • SectionHeader renders its 14px uppercase label as an <h3>, so the document outline jumps from h1 to h3.
Fix: name the roles (display, title, heading, subheading, lead, body, label, meta, caption) as classes in one file. Then set the global h1–h5 rules to what pages really use, or delete them.
MediumF5 · duplication

Blog prose and case-study prose are two copies that have drifted apart

A detail that's easy to miss: Preflight sets list-style: none, and the blog styles never set it back. No published post has a list yet, but the first one will render with no bullets, just indented lines. The About page's Skills and Interests lists have no markers for the same reason (which may be what you want there).

Fix: one shared .prose stylesheet (in @layer components) that both templates use, with the case-study design choices (accent bullets, blockquote rule) applied to both.
MediumF6 · dead CSS

About 100 lines of Nav styles never apply

The dropdown markup comes from the React island NavDropdown.tsx. Astro's scoped styles only reach markup in the same .astro template, so the .menu-button, .menu-content, .nav-items, .link, .socials and .social rules in Nav.astro:79-175 match nothing. The live versions are the global ones in global.css:285-370, and their values conflict (for example .nav-items gap 1rem vs 4px, padding 2rem vs 8px).

Other dead rules: [data-theme='light'] .menu-button (global.css:315; the site never sets data-theme), .hero p and .roles in index.astro:99-106 and 145-149, and the unused component HeroTyper.tsx.

Fix: delete them. If you want the dropdown styles next to the component, move them into a CSS file that NavDropdown.tsx imports.
MediumF7 · architecture

Component styles sit in global scope with generic names

.button, .link, .menu-button and .nav-items are unlayered global classes. .button also carries margin-top: 20px, a layout decision inside a component. Because they're unlayered, adding a utility like class="button mt-0" won't remove that margin (see the cascade above). .link is generic enough that it'll collide with something eventually.

Fix: wrap component rules in @layer components { … } so utilities can override them, and drop the margin from .button.
MediumF8 · color

Nine reds, and the hover state is barely visible

Light-mode hover goes from #ff4949 to #f54c4c, which is almost the same color, so hovering a button or link shows almost no change. The naming is also reversed: --accent-light is #600202, the darkest red, and nothing uses it. Hardcoded reds appear in PasswordModal (hsl(0 80% 60%), hsl(0 80% 65%)), BackgroundEffect (#ff4949 fallback) and gradients (#ca7879).

Fix: --accent, --accent-hover (a visible 8–12% shift), --on-accent and --danger. That's four roles, each with a light and dark value.
MediumF9 · React

React components style themselves with inline objects

PasswordModal, PhotoModal and CaseStudyCarousel each build the same overlay chrome by hand: rgba(0,0,0,.9) backdrop, white ✕ at 2rem, ‹ › arrows at 2.5rem and 1rem insets. Inline styles can't express :hover, :focus-visible or media queries, which is why two of them inject <style> tags. The password field's focus state relies on the global outline only.

Fix: a small overlay.css (backdrop, close, prev/next) imported by the three components.
LowF10 · fonts

Two Google Fonts families load but are never used

MainHead.astro:44-47 requests Public Sans and Rubik. Nothing references either one. Roboto Mono loads its full 100–700 variable range plus italics, but the site only uses 400 and 500.

Fix: remove the first <link> and request Roboto+Mono:wght@400;500.
LowF11 · tokens

Unused tokens left over from the starter template

No live code uses --gray-50, --gray-500, --gray-700 (except inside a gradient), --gray-999_40, --gray-999-basis, --accent-light, --accent-subtle-overlay, --gradient-accent or --gradient-accent-orange. The dark-mode --accent-subtle-overlay is purple (hsla(281…)), which suggests these came from Astro's portfolio starter and were never cleaned out. --gray-100 is used only by the global heading default, which every page overrides.

LowF12 · scales

Radius, spacing and breakpoints have no shared scale

  • 13 distinct radii: 2px, 0.25, 0.375, 0.5rem, 8px, 0.75, 0.9375, 1rem, 20px, 1.5rem, 50%, 999px, 999rem.
  • Spacing tokens exist, but only Tailwind utilities use them. Scoped CSS writes raw values (40px, 24px, 2.5rem, 3.5rem…).
  • Five breakpoints: 50em, 59.99em / 60em, 64em (written as 1024px in Footer), 70em. Tailwind only knows lg = 60em, and its sm/md/xl are still the defaults.
  • The 83rem wrapper is redefined by hand in Nav.astro:58-61 and Footer.astro:32-38 instead of using .wrapper. The reading-column grid (1fr 60% 1fr) is copied 3 times.
LowF13 · Tailwind scanning

Tailwind generates utilities from words that aren't classes

The built CSS includes .start{inset-inline-start:…}, .container, .table, .grid, .hidden, .border and .resize. Tailwind found them in prose and props. Hero's align="start" becomes class="start", which then matches the Tailwind utility as well as Hero's own .start. It's harmless today, but it's a namespace collision waiting to happen. @source not for the content folders would tighten this up.

03

Suggested cleanup order

For this branch. Each step is small enough to review by itself, and the order keeps the visual changes separate from the plumbing.

  1. Serve the font. Add Aktiv Grotesk as a real webfont, drop Public Sans and Rubik, and trim Roboto Mono (F1, F10). This is the biggest visible change and the smallest diff.
  2. Delete dead CSS. Remove the Nav.astro dropdown rules, the data-theme rule, the index.astro leftovers, HeroTyper and the unused tokens (F6, F11). This should change nothing visually, so it's a good first refactor to check against screenshots.
  3. Rename tokens to the v4 namespaces. --text-*, --font-*, and add --radius-* and --breakpoint-* (F3, F12). Mechanical find-and-replace.
  4. Add a semantic layer on top of the ramp. --fg-strong, --fg, --fg-muted, --fg-subtle, --border, --surface, --surface-raised, --accent, --accent-text, --accent-hover, --on-accent, --danger. Fix the red contrast here (F2, F8).
  5. Type roles in one file. .t-title, .t-heading, .t-lead, .t-label, .t-meta and so on, plus a shared .prose. Replace the six page-title copies and the two prose copies (F4, F5).
  6. Layer it. Move global component rules into @layer components, pull the dropdown and overlay styles into their own files, and remove the !importants that are no longer needed (F7, F9).

Proposed file shape: styles/tokens.css (primitives + semantic, light/dark) → styles/base.css (body, headings, links, focus) → styles/components.css (button, pill, prose, overlay) → global.css that just imports them along with Tailwind.

Color

One 12-step blue-gray ramp that inverts between themes, plus one red accent. The ramp numbers mean "distance from the background": 0 is the strongest ink and 999 is the page itself.

Contrast is measured against that theme's page background (gray-999). AA ≥ 4.5 · AA large ≥ 3 · fail < 3. Usage counts exclude global.css itself.

Spacing & layout

A 4px-based scale lives in @theme, but only Tailwind utilities read it. Scoped CSS mostly writes raw rem and px values that happen to land on the same grid.

Layout primitives

  • Wrapper: max-width: 83rem, padding-inline: 1.5rem. global.css:65-70 Re-implemented by hand in Nav and Footer.
  • Reading column: grid-template-columns: 1fr 60% 1fr at ≥60em, on About, blog post and case study (3 copies).
  • Page rhythm: .main-content-wrapper gap 2.5rem → 4rem at 60em. BaseLayout.astro:83-94
  • Nav: 1.5rem padding, 3.5rem bottom margin.
  • Card padding: 40px. Section grid gap 32px. Project grid gap 2em.
  • Home: gap-20 (5rem) between hero and main, and lg:gap-48 (12rem) between sections.
  • Prose: p + p 1.5em, li + li 0.5em, h2 top 2.5rem, h3 top 2rem.
07

Radius, shadow, motion

Radii in use (13)

Suggested consolidation: --radius-sm: 0.5rem (buttons, inputs, menus) · --radius-md: 0.75rem (cards, modals) · --radius-lg: 1.5rem (images, desktop cards) · --radius-full: 999px (pills, toggles). Everything else maps onto one of these four.

Shadows

--shadow-sm · cards, photos
--shadow-md · hover, images, modal
--shadow-lg · dropdown menu

Each one is four stacked layers. In dark mode they become faint white glows (toggle Dark to compare), which barely show against #090b11, so dark mode effectively has no elevation.

Motion

  • --theme-transition: 0.2s ease-in-out: link underlines, card shadow, filters, theme toggle. 13 uses. One hardcoded 0.2s ease in Hero.
  • Page intro fadeInFromTop (1s ease-out, 10px) plays once per session. Dropdown slideDownAndFade is 0.2s.
  • Only ThemeToggle checks prefers-reduced-motion. The About carousel and the three.js background run regardless.
